# LLM API Chat Roles

Large Language Model (LLM) APIs process conversational threads using a structured array of message objects. Each object contains a `role` and the corresponding message `content`. 

Understanding how to map and leverage these roles is fundamental to building reliable chatbots and autonomous agents.

---

## 🎭 The Four Core Roles

| Role | Target | Responsibility |
| :--- | :--- | :--- |
| **`system`** | Model Behavior & Constraints | Set instructions, boundaries, output formats, and safety guidelines. |
| **`user`** | Human Operator / Input Data | Feed questions, commands, and target payloads to be processed by the assistant. |
| **`assistant`** | Model Response Output | Represent previous answers generated by the LLM, establishing dialogue continuity. |
| **`developer` / `tool`** | System Executions / Tools | Send the results of calling an API, reading a file, or running a CLI command back to the model. |

---

## 🔄 Conversational Memory Flow
LLMs are stateless. They do not "remember" previous conversations. To create the illusion of memory, the client application must append every question and answer to a `messages` array database and send the entire history to the LLM on every subsequent request.

### Conversational Memory Example
```
1. User Query: "What is React?"
   Messages DB: [
     { role: "system", content: "You are a brief computer science tutor." },
     { role: "user", content: "What is React?" }
   ]
   ─── Send to API ───> LLM outputs: "React is a UI library."

2. User Query: "Who created it?"
   Messages DB: [
     { role: "system", content: "You are a brief computer science tutor." },
     { role: "user", content: "What is React?" },
     { role: "assistant", content: "React is a UI library." },
     { role: "user", content: "Who created it?" }
   ]
   ─── Send to API ───> LLM outputs: "Facebook (now Meta)."
```

---

## 🛠️ Mapping Custom Tool Execution Roles
When building custom loops (where we write the tool runner execution directly in JavaScript), the feedback from the tool execution is fed back into the `messages` array:

1. **OpenAI**: Uses the `tool` or `developer` role, mapping directly to tool function calls.
2. **Gemini**: Requires alternating `user` and `model` role patterns. When a tool outputs a response, we feed the tool result back using the `user` role so the model parses it as input for its next decision block.

### Example Tool Feedback Payload
```javascript
MESSAGES_DB.push({
  role: "user", // Feed back to Gemini as user role
  content: JSON.stringify({
    step: "TOOL_OUTPUT",
    output: "The weather in Goa is 30°C and Sunny."
  })
});
```
